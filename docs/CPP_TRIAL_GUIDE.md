# C++ 指针课程试用指南（P5.1）

供第一轮学生/教师试用《理解 C++ 指针：从变量地址到内存操作》。

## 环境准备（教师执行一次）

```bash
# 1. Docker Desktop 运行中，构建三个沙箱镜像（一次性）
docker build -t projectweave-sandbox-python:3.12 backend/sandbox/python
docker build -t projectweave-sandbox-cpp:clang15-bookworm backend/sandbox/cpp
docker build -t projectweave-sandbox-cpp-debug:clang19-trixie backend/sandbox/cpp-debug

# 2. 启动后端（8000 被占用时用 8001）
cd backend && .venv/Scripts/python.exe -m uvicorn app.main:app --port 8001

# 3. 启动前端（另开终端；端口对应）
cd frontend && BACKEND_PORT=8001 npm run dev
```

打开 http://localhost:5173

## 学生操作流程（约 20-30 分钟）

### 1. 创建项目（1 分钟）

首页「创建项目」→ **技术栈填 `C++`** → 提交。系统自动生成：
- 《理解 C++ 指针》课程的 3 个任务（左侧「任务」页签）
- 每个任务的初始代码与测试文件（src/tasks/ 目录）

### 2. 初始诊断（3 分钟）

项目详情页 →「能力诊断」→ 回答 6 道左右 C++ 概念题（&、*、指针关系、
值传递/引用传递）。提交后系统按 cpp.* 知识概念记录三档初判。

### 3. 任务一：变量与地址（5-8 分钟）

1. 打开 `src/tasks/task1_address.cpp`，先**运行**（▶）观察值与地址的输出差别
2. 把代码中的 `TODO(任务1)` 改成打印 y 的地址（模仿上一行）
3. 在 printf 行**行号左侧点击**设断点 → 点工具栏 🐞「调试」
   → 暂停后在右侧「调试」页签看真实局部变量
4. 点「运行任务测试并验收」——真实编译执行判定，通过后进入任务二

卡住了？右侧「AI 导师」提问。它会按层级给提示（方向 → 概念 → 结构），
**默认不给完整答案**；确实需要答案时勾选"答案级帮助"。

### 4. 任务二：指针与解引用（核心实验，8-10 分钟）

1. 完成 `*p = 20;`（TODO 任务2a）
2. 在该行设断点启动调试——**教学画布**出现内存图：
   `p → x` 的箭头是**真实地址匹配**验证的（不是示意图）
3. 点工具栏「单步跳过」执行赋值——观察画布中 x 的值 10 → 20 变化高亮（↻）
4. 运行任务测试验收

### 5. 任务三：函数参数与迁移练习（5-8 分钟）

1. 完成 `bump`（指针版）与 `bump_ref`（引用版）
2. **迁移练习**：在测试文件里独立实现 `my_swap`（交换两个 int）——
   检验你是否真正理解"通过地址修改外部变量"，任务描述不含答案
3. 运行测试验收；可在 bump 内设断点看「调用栈」的两个真实栈帧

### 6. 完成后

项目详情页可看到任务徽标全部「已完成」；「学习事件」页签有 3 条
task-evaluated 记录（信任级 practice）；知识图谱页的 cpp.* 概念
出现掌握徽标（application 维，基于真实验收证据）。

## 观察要点（教师）

- AI 提示是否遵循渐进层级（H1 方向 → H2 概念 → H3 结构；H4 需显式勾选）
- 内存图的"未解析指针/空指针"标注是否被学生正确理解（不虚构指向）
- 单步后变量变化高亮是否帮助学生建立"预测 → 验证"习惯
- 学生在迁移练习（my_swap）的独立完成率

## 已知边界（如实告知学生）

- 堆指针（new 出来的）在内存图中标"地址未解析"——它不指向任何具名变量，这是真实数据的诚实呈现
- 测试/验收信任级为 practice（练习）；正式认证需要服务端受保护测试（后续阶段）
- Python 项目暂无课程（脚手架可用，学习路线为空——如实标注）
